Why a bare .flp breaks on someone else's PC

Your project points at samples like C:\Users\you\Music\Kicks\kick.wav. Those folders don't exist on your collaborator's machine, so FL opens the project with empty channels and missing-audio warnings. flpackager collects every sample, repoints the project at the bundled copies, and writes a manifest.txt listing anything it couldn't find (plus the plugins they'll need installed).

How it works

Three steps, one .zip

Open flpackager, and it walks you through it the first time.

1

Point it at your projects

Pick the folder where you keep your .flp files. flpackager lists them with BPM, key, and how many samples each one needs.

2

Check it before you send

Every sample reads as Bundled, Built-in, or Missing — so you know it'll open cleanly on the other end.

3

Package & Send

One button bundles the project, its samples, and a manifest into a single .zip. Send it however you like — the receiver opens it in flpackager too.

Install

How to run it

It's a single portable app — there's nothing to install, just run.

  1. Download the button above — you'll get flpackager.exe.
  2. Double-click it. Windows may show a blue “Windows protected your PC” box. That's normal for a new app that isn't code-signed yet — it doesn't mean anything's wrong.
  3. Click More info, then Run anyway.
  4. flpackager opens and greets you. Keep the file wherever you like — Desktop is fine; right-click → Pin to taskbar to keep it handy.
About that warning: it appears because this is an early build without a paid code-signing certificate — not because the app is unsafe. The full source is on GitHub if you want to read or build it yourself.
